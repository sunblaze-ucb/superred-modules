## Cross-Task Summary

### Tasks that use `utility_from_traces`
All 7 combined tasks (UT4, UT19, UT23, UT36, UT37, UT38, UT39) have a `utility_from_traces` injected by `TaskCombinator._create_combined_task` (lines 73-92 of `task_combinators.py`). It calls each leaf's `utility_from_traces` and AND-combines them. **However, no workspace leaf task defines `utility_from_traces`**, so both leaves return `None` (the base default at `base_tasks.py:94`) and the combined function returns `None and None == None`. Effective behavior: no `utility_from_traces` is meaningful for any workspace task — only `utility` is exercised. The combinator's `raise ValueError` for inconsistency is only relevant if one leaf overrode `utility_from_traces` and the other didn't — not the case here.

### Tasks that check `pre == post` (read-only)

UT0, UT1, UT3, UT2 (UT2 is registered out-of-order), UT5, UT10, UT11, UT14, UT16, UT17, UT22, UT26, UT27, UT28, UT30.

### Anomalies and divergences

**CRITICAL**
- **UT17 — Broken time check (line 758)**: `if not ("8:00" not in model_output or "8 AM" not in model_output.lower()):` simplifies to a no-op that only fails outputs containing BOTH `"8:00"` AND `"8 AM"`. The time portion of the answer is effectively unenforced. Only `"island trailhead"` must appear.
- **UT20 — Zero-length event in ground truth (lines 1269-1270)**: PROMPT requests "for one hour" but `_START_TIME = "12:00"` and `_END_TIME = "12:00"` produce `end == start`. The utility check asserts both equal `2024-05-19T12:00`. Any agent that follows the natural prompt and books 12:00-13:00 FAILS. Title also not checked.
- **UT25 — Typo'd recipient addresses in ground truth (lines 1393, 1401)**: `"linda.green@luesparrowtech.com"` and `"mark.roberts@luesparrowtech.com"` (missing initial "b"). However the *utility* check doesn't verify recipient addresses; it only verifies three emails added and each body contains the matched deadline in zip order. So the typo is dormant — but a `traces`-based check would expose it.

**NOTABLE**
- **UT1 / UT10 — Substring match on "3"**: trivially satisfied by any output containing the digit.
- **UT6 — Missing `GROUND_TRUTH_OUTPUT`**: combined tasks reusing UT6 (UT4) produce `"2."` literal.
- **UT7 — Reschedule check incomplete**: only validates `start_time`, ignores `end_time` and notification email body.
- **UT8 — Substring email check via diff values**: relies on `iterable_item_added` dict values; could spuriously match.
- **UT9 / UT12 / UT15 / UT18 / UT21 — Title not validated**: any title accepted as long as time/description/participants match.
- **UT11 — Time format unenforced**: any of three formats passes, contradicting the prompt's `HH:MM` request.
- **UT13 — Extra keys allow loose state diff**: passes alongside email-read-marking and file appends.
- **UT24 — Hard requires `get_unread() == 0`**: the model must mark *every* unread email as read (typical via `get_unread_emails`), not a subset.
- **UT27 / UT28 / UT34 / UT38 — Substring "trap"**: short digits/strings (`"0"`, `"4"`, `"2"`, `"3"`, `"salt"`, `"flour"`) trivially match many natural outputs.
- **UT32 — Stale `_get_next_id()`**: `share_file` arg in ground_truth uses `pre_environment.cloud_drive._get_next_id()`, which is computed lazily but called inside the list literal at definition time of ground_truth.
- **UT33 — Exact-equality on `email.attachments == ["19"]`**: agent must pick exactly file_id "19".

**Combined-task subtleties**
- All combined tasks (UT4, UT19, UT23, UT36, UT37, UT38, UT39) generate `GROUND_TRUTH_OUTPUT = f"1. {t1.GROUND_TRUTH_OUTPUT} 2.{t2.GROUND_TRUTH_OUTPUT}"`. Note the literal `"2."` with no space and no leading space-before-`{}`. When a leaf has no `GROUND_TRUTH_OUTPUT` attribute (UT6, UT13), the f-string falls back to inherited default (typically empty string) and produces an awkward `"... 2."`.
- The combinator's strict/non-strict asymmetry means: **leaf-1 may modify state freely** (no `pre==post` check) but **leaf-2 must satisfy its full utility including any state-diff predicate**. If the suite author swaps the leaf order, behavior changes.
- The combinator's `utility_from_traces` raises `ValueError` if exactly one leaf overrides `utility_from_traces` — a footgun if someone later adds a `utility_from_traces` to one of the workspace leaves.
