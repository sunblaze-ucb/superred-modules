## Copied byte-for-byte

- `_vendor/dt_multilingual/template.py` — `MultilingualTemplate.enhance` (the
  translation prompt with its two worked examples) and
  `MultilingualTemplate.is_translation` (the translation-check prompt). The
  file has no imports and is loaded directly.
- `compliance.build_compliance_check_prompt` — reproduced verbatim from
  `single_turn/compliance.py`. That module could not be vendored whole because
  it imports DeepTeam's `generate` helper; `scripts/sync_upstream.py --check`
  re-extracts the upstream function and asserts the produced prompt is
  byte-identical.
- `get_additional_instructions` — the "reason in the same language, then reply
  in English" tail, verbatim.

## Upstream coverage

`multilingual.py` defines one attack; its whole `enhance` is ported:

| Upstream step | Ported |
| --- | --- |
| `MultilingualTemplate.enhance` translation prompt | yes |
| `EnhancedAttack` parse (`translation_logic`, `input`) | yes |
| append `get_additional_instructions` | yes |
| compliance gate (`evaluate_generation_compliance`) | yes — reproduced prompt, `non_compliant` parse |
| is-translation gate (`MultilingualTemplate.is_translation`) | yes |
| accept iff `not non_compliant and is_translation`, else retry | yes |
| `max_retries` loop, fall back to the original request | yes |
| `language` parameter (specific or auto-select) | yes |

Not ported: the `tqdm` progress bars, `initialize_model`/`generate` model
plumbing (the framework injects `self.llm`), and the `a_enhance` async twin
(superred drives one path). The `ComplianceData.reason` field is generated by
the model but not acted on upstream either, so only `non_compliant` is read.

## Deviations

### 1. Translate once at initialize

Upstream `enhance` produces one attack string. superred drives attempts through
the event loop, so the gated translation happens at `initialize` and the
result is injected on the run.

### 2. A genuine budget exhaustion propagates

Any attacker-LLM failure is a retry, **except** a `BudgetExhaustedError` with
`usage.cost > 0`, which is re-raised — otherwise a spent budget would exhaust
every retry and silently fall back to the un-translated goal, reporting a run
the target never defended. The budget-less noop client (nothing spent) still
falls back.

### 3. Unreadable gate replies do not accept a turn

Upstream's pydantic `generate` would raise on an unparseable compliance or
is-translation reply, forcing a retry. Here the parsers return `None`, and the
acceptance test requires `non_compliant is False and is_translation is True`,
so a `None` on either gate declines the candidate and retries — the same
outcome, without an exception.

### 4. Injection-surface selection (superred adaptation)

Follows the house pattern (`muzzle`, `chord_xthp`, `eia_agent`, `gepa_agentic`,
`poisonedrag`, `agentvigil_websentinel`): a byte-identical `surface_llm.py`,
with `classify_controllables` at `initialize` picking the user-prompt surface.

Note: the shared `surface_llm.py` pins `temperature=0.0`, which the repo's
`test_no_temperature.py` guard forbids. The six merged classifier modules omit
the guard; this module keeps it and skips only that one pinned shared file.

## Known limitations

- Three attacker-LLM calls per accepted translation (translate, compliance,
  is-translation), plus retries.
- Effectiveness depends on the attacker model's translation quality into
  low-resource languages, and on the target actually being weaker in them.
